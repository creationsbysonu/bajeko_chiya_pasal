--------------------------------------------------------------------------------
1. WHAT IT IS
--------------------------------------------------------------------------------
A production-oriented web app that streams Nepali music as themed "radio worlds"
— golden-age Radio Nepal classics, chiya-pasal (tea shop) mornings, bus-yatra
highway anthems, lok dohori, prem geet, biraha, Nepali rock and modern indie —
wrapped in the nostalgia of vintage radios, steaming tea glasses and festival
seasons (Dashain, Tihar, Chhath).

Every playback is an official YouTube embed. No audio files are downloaded,
proxied, extracted or hosted by this project. There is no traditional backend
server: the frontend is a static React SPA (Vercel) that talks directly to
Supabase (Postgres + a locked-down SQL RPC layer).

Formerly named "Purano Dhun"; rebranded to "Bajeko Chiya Pasal" across the
entire codebase (UI strings, i18n, PWA manifest, metadata, storage keys,
service-worker cache names, docs, SQL headers).

4. ARCHITECTURE & DATA FLOW (end to end)
--------------------------------------------------------------------------------
1. Browser loads the SPA shell from Vercel's CDN.
   - The service worker (sw.js) serves the shell network-first (so a fresh
     deploy is live instantly) and falls back to cache, then offline.html.
2. App.tsx mounts → api.ensureListenerSession() performs an anonymous Supabase
   Auth sign-in (cached; catalog still works if anonymous auth is disabled).
3. App.tsx loads the front page in parallel:
     get_stations()          → 10 themed radio worlds
     get_featured()          → featured / trending / new song lists
     get_songs(sort=trending)→ trending
     get_songs(sort=new)     → new releases
     get_genres()            → genre list
     get_genre_categories()  → 5 categories (classical_traditional, folk,
                               popular, regional, special)
     get_decades()           → 7 decades (1960s…2020s)
     get_songs(mood=tea-shop)→ the chiya-pasal queue for the Tea Shop panel
4. Every RPC goes through services/api.ts → supabase.rpc(fn, args) as the anon
   role. Response shapes match the old Django REST API, so components consume
   plain typed objects (src/types/index.ts).
5. The user picks a song or station → PlayerContext queues it → the official
   YouTube IFrame API plays it inside a single persistent hidden container
   (#bajeko-chiya-pasal-yt-iframe-slot). The iframe is never removed from the
   DOM, so audio survives route/tab changes.
6. Playback telemetry: log_playback_event() RPC (identified, deduplicated,
   flood-capped on the server).
7. Favorites: add_favorite / remove_favorite / get_favorites, keyed to the
   anonymous auth user; the locally-recent list (localStorage) powers
   "Recently Played" even before the network answers.

--------------------------------------------------------------------------------
7. SECURITY MODEL
--------------------------------------------------------------------------------
- RLS: deny-all on every table; the public never reads a table directly —
  everything goes through SECURITY DEFINER RPCs (0004_rls.sql).
- 0005_security_hardening.sql: revokes EXECUTE on `_`-helpers, requires the
  claimant email for takedown status lookups, bounds free-text input length.
- 0006_abuse_controls.sql: playback telemetry is identified, deduplicated and
  flood-capped; takedown submissions rate-limited (5/hour); public taxonomy
  reads return active rows only.
- 0009_song_requests.sql: validated + throttled "Recommend a song", a
  contact-free public feed, and admin moderation RPCs.
- The frontend only ever holds the anon key. service_role never ships to the
  client. Auth: anonymous Supabase sessions; admin identity is an email
  allowlist checked inside the SQL functions themselves.
- Content licensing: only official YouTube embeds; oEmbed is used to verify
  that each catalog entry points at a real, embeddable, correctly-attributed
  video.

10. PLAYBACK ARCHITECTURE (important design constraint)
--------------------------------------------------------------------------------
All audio comes from the official YouTube IFrame Player API (youtube.com embed).
This is deliberate: the project never downloads, proxies, extracts or hosts
audio, which keeps it inside YouTube's terms of service.

Consequences (by design, documented in PlayerContext):
  • The media element belongs to YouTube's cross-origin document, so the OS
    grants background/lock-screen playback to *that* document, not ours.
  • Locking the phone therefore stops the music on iOS (near-certain) and
    Android (usually). Our page cannot override it.
  • The reliable in-browser mitigation shipped today is the Screen Wake Lock
    toggle: keep the display awake while playing, so the lock never happens.
  • The only way to get true lock-screen playback (controls, resume after
    hours, screen off) is to own or license the audio and play it from a real
    <audio> element with Media Session — a deliberate future option, not
    implemented.

11. CONTENT & CATALOG PROVENANCE
--------------------------------------------------------------------------------
• Every song entry points at a real YouTube video, verified via YouTube oEmbed
  (embeddable, correct title/attribution).
• "Heart touching" festival titles are mapped to thematically-close *real*
  videos rather than invented tracks.
• Editorial QA: no typos in Nepali copy, short labels only, no AI-sounding
  filler, no emoji.
• Attribution is stored per song and surfaced in the UI; rights holders have a
  takedown path with an admin moderation queue.

about 2 minutes; a daily visit keeps it warm.
